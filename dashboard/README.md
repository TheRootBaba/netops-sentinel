# NetOps Sentinel Dashboard

A lightweight Python HTTP dashboard for viewing monitoring reports and incident history, accompanied by a JSON-based alert checker.

## Requirements

- Python 3.10 or later
- Monitoring data generated by NetOps Sentinel
- Access to the GNS3 VM runtime data directory

## Runtime data

The current VM deployment expects `/home/gns3/netops-sentinel-data`, containing:

- `evidence/runs/` — timestamped reachability reports
- `incidents/incidents.json` — incident history
- `incidents/alert_state.json` — alert-processing state

Runtime reports and incident data are generated separately and are not included in the source repository.

## Start the dashboard on the GNS3 VM

From the directory containing `dashboard.py`, run:

```bash
python3 dashboard.py
```

The server listens on `127.0.0.1:8080`, so it is accessible locally on the VM. To view it remotely, use an SSH tunnel rather than exposing the development server directly to a network.

## Process incident events

After new monitoring reports have been generated, run:

```bash
python3 alert_check.py
```

The checker processes new reports, records an outage after two consecutive unreachable reports, and records recovery when an endpoint becomes reachable again.

## Limitations

- The data path is hard-coded for the GNS3 VM.
- Incident state is stored in JSON files, not a database.
- The alert checker does not schedule monitoring itself.
- The dashboard and alert-processing workflow still require verification against the intended VM runtime data.
- This is a lab project, not a production monitoring or incident-management platform.
